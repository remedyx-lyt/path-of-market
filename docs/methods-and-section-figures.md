# 金融方法实际使用与按论点选图

2026-10-24（Australia/Sydney）。用户要求充分利用已保留的金融 Skill，让模型主动选择有用的分析和图表；不能只把文件存下来，也不能机械每节凑一张。沿用 React → Java → Python；本任务没有实现会话持久化、侧栏聊天或估值系统。

## 检查旧版所得的结论

旧案例 `9636131a-13ba-4f6e-ae14-7f3660dc3731` 的确加载了产品适配规则与原版 `earnings-analysis`，但实际工具记录没有一次 `read_research_skill`。业务收入、研发等事实在文字里出现，图表仍只有四类财务总览。16个原版文件库已保留不等于16个方法都执行；此前不能声称“充分用好”。

我们保留的16个原版Skill分两组：

| 类别 | 方法 |
| --- | --- |
| 公司/业绩/行业研究 | initiating-coverage、earnings-analysis、earnings-preview、sector-overview |
| 持续比较与线索 | model-update、thesis-tracker、catalyst-calendar、idea-generation、morning-note |
| 财务与估值方法 | 3-statement-model、competitive-analysis、comps-analysis、dcf-model |
| 底稿制作与核查 | clean-data-xls、audit-xls、xlsx-author |

原版位置、固定commit、36个原始文件及许可沿用 [财务研究说明](financial-research-skill.md)。原文件没有修改。这里是产品适配，不能将上游的固定25张图、逐子任务确认、评级、Claude工具或付费数据环境当作本产品要求。

## 现在如何用到原版方法

1. `core/research_skills.py:load_method_bundle` 按任务选择相关原版参考，逐段完整读取并核对原始哈希。综合公司研究选择公司研究、图表、质量检查、观点验证；经营/财报问题再加入财报分析workflow，竞争问题加入竞争框架。不是把所有16个无条件塞入上下文。
2. `AgentRunner.prepare_methods` 将完整选中内容实际发送给模型，产生研究主线、要回答的问题、所需证据、图表建议与暂不可完成的方法。`methodUsage.references` 保留文件、完整字符数与哈希，`plan` 保留计划。长参考不是只送前10000字。
3. 主研究模型带着计划自主选择工具，取得证据后可以调整主线和选图。另有 `read_research_skill` 用于继续按需回查原版细节。
4. 证据足够后，决策模型返回ready，程序进入独立的JSON报告写作阶段，避免把长篇报告与工具决策挤在同一次6500-token输出里。图文正文与复核使用14000-token输出上限，文字上下文仍160000字符，累计预算不变。这个上限不是承诺输出固定字数。
5. 报告复核收到方法计划、真实数据和候选内容，再核对增长驱动、业务结构、现金质量、反方证据与图文一致性。`reviewed` 只表示做过这次模型复核，不是独立分析师审计，更不能证明原版方法所有环节都达到专业标准。

没有一致预期数据时不做超预期/低于预期判断，没有估值输入/模型工具时不宣称完成DCF，没有Excel工具时不宣称三表工作簿已制作。先进方法可读与方法可执行继续区分。

## 数字怎样成为图

新逻辑工具 `extract_report_data(documentId,pages,focus)`：读取已经完成全文文字处理的PDF中1至4个物理页；模型返回原始数值、单位、年份、期间、连续原文引文；程序核对原文、数字、指标标签、单位和期间，计算并生成受控绘图数据。全文阅读不能被指定页取数替代。

全文处理后自动定位主营收入构成、研发投入、合并报表，作有限的分批取数；跨页表头与正文联合定位。模型还能自主指定页补查或用原页视觉工具核对复杂表格。单个坏条目排除并记录缺口，不把同批有效条目一起丢掉；所有条目无效仍需修复或失败。失败诊断和派生缓存只写忽略的storage目录。

新增结构化金额：营业成本、总负债、货币资金、应收账款、存货、研发投入；原有研发费用单独保留。程序计算毛利率、资产负债率、研发费用率/研发投入占比。对同一数据的万元/亿元舍入披露，只在差异落入明确的原始精度舍入范围时选更精确值；真实冲突仍排除，不能用这个规则静默处理重述。

`report_figures.py` 单独处理产品/地区/行业收入，三个维度分别统计。占比分母是同期合并营收；分项缺少时差额标“其余收入（总额扣除）”，不能将已知项归一为100%。分项超出总额、金额冲突、缺总额时不画。历史分类变化保留原披露名称，不擅自合并。

“底稿”由程序从已取得的文字或表格生成，无需用户手工做Excel。PDF正文中带金额与单位的句子也可取数；全网文章发现/全文读取尚未接入，不能把PDF文字支持说成任意网页已经支持。

当前金额核对并不能独立验证所有表格列序、会计口径与归因；复杂情况需要原页复核，扫描页无文字校对的金额继续不进入这条自动核对路径。

## 模型如何主动选图

`financialData.charts` 与 `businessData.datasets` 是程序依据实际证据提供的候选菜单。模型在章节里通过 `chartIds`、`businessIds` 选择需要的图，决定放在哪节、用于支持什么判断。程序校验ID和引用，不接受任意HTML、JS或模型编造的数值。

- 时间变化可用柱/折线；产品与地区结构可用环形占比图和历年堆叠柱图。
- 盈利可选净利率/毛利率，现金流可选利润与现金对比，资产质量可选资产负债、资金/应收/存货，研发可选金额及占比。
- 定性逻辑与风险可用带逐节点来源的cards/flow，不编风险分数/概率。flow不把相关性包装成已证实因果。
- 不要求每节一张。概览、口径说明等可以不画；重要部分有可用数据却全部闲置时提示模型完善。已有量化数据但都没选、已取得业务结构却只选财务总览时，最终校验会要求主动选用。
- 同一图放最相关的章节，年度与半年分开切换。未支持的瀑布、散点、估值敏感性等不能因为方法计划建议了就宣称已绘制；可改用已支持图型或说明缺口。

前端 `BusinessCharts.tsx`、`FinancialCharts.tsx` 与 `ResearchReport.tsx` 将所选图嵌入章节，金额与占比可展开核对来源。旧报告没有新字段仍按原总览展示。

## 检查

`scripts/check-report-figures.py` 验证完整方法实际发送、任务路由、原文取数、维度/占比/冲突、缺项差额、跨页定位、精度、定性引用与无每节配额。`scripts/check-section-figures-web.mjs` 验证真实已完成案例、按章图表、来源、响应式、异常数据和旧报告兼容。真实运行、用量、局限和截图以 `current-state.md` 本轮记录为准。

## 输出与上下文边界

依据[DeepSeek官方Chat Completions文档](https://api-docs.deepseek.com/api/create-chat-completion/)，max_tokens限制生成长度，finish_reason=length不代表完整结果。报告写作独立于工具决策，截断的工具参数不执行。供应商返回的无效/截断响应若带有效用量，也计入运行账本。决策/提取仍有6500输出边界，文字阅读仍使用原配置上限，报告正文与复核14000。

完整阅读笔记与页原文留在派生缓存/运行状态；主模型使用有来源的有限投影，保留最近两次回查全文，更旧回查留摘录。无效报告草稿写入忽略的诊断目录，只把明确校验问题回传，不把整份错误草稿反复堆入主上下文。以上不是JSONL会话持久化或自动compaction。
