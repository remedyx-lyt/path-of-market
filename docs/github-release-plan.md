## 后续更新计划的写法

- 近期：日常稳定性、已证实的模型兼容、来源冲突处理、资料与预算失败的恢复体验。
- 中期：更清晰的证据定位、报告导出、图像/复杂表格阅读，以及可控的搜索备用渠道。
- 长期：板块追踪、持续变化对比、不同研究风格与机会跟踪等最初产品特色。

已实现、实验性和计划中分别标注；路线图不当成功能宣传图。

## 怎么上传，以及上传之后怎么看

上传代码与部署在线应用分开处理。首发把代码、README、图片/GIF 与运行说明放到 GitHub，别人无需运行就能了解成果；实际应用仍按说明本地启动。此轮不新增云部署、域名或服务器维护。

1. 整理完 README、素材与检查后，本地提交。当前已有 `main` 和完整历史，不再 `git init`，不需要重新拷贝成一个只有最终代码的新目录。
2. 在用户 GitHub 账户创建一个空仓库；建议短英文名 `path-of-market`（仅建议，尚未确定）。不要勾选由 GitHub 生成 README、`.gitignore` 或 LICENSE，避免与本地历史冲突。公开展示需要仓库设为 Public。
3. 登录 GitHub 后，在项目目录把网页给出的真实远程地址加入并推送：

   ```powershell
   git remote add origin https://github.com/<GitHub用户名>/<仓库名>.git
   git push -u origin main
   ```

   地址中的占位文字必须替换成实际仓库；这段是说明，本轮没有执行。也可以授权后由 GitHub CLI 建立并推送同一个本地仓库。
4. 在 GitHub 网页核对 README 图片、GIF、相对链接和许可证；填写 About 一句话简介及相关 topics，在个人主页置顶。首发检查完成后可建立 `v0.1.0` Release，附功能范围、已验证案例、限制与后续计划。
5. 求职材料链接到仓库首页；如需要短视频，后续补 60–90 秒演示。首发不强制单独做介绍网站，也不需要把整个 Python/Java 应用塞进 GitHub Pages。

官方步骤：[把本地代码加入 GitHub](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github)。最终是否创建远程仓库和推送由后续明确的发布指令触发，当前只做准备计划。
