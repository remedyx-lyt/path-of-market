# 数据来源

## MVP 策略

第一版由系统自动发现并获取公开原始资料，上传文件作为补充。M1-2 先完成巨潮公开年报；其他公告、季报、研报、网页正文和行情 Provider 按后续任务接入。选定研究资料默认通读，长材料分批阅读；搜索摘要与关键词不代替原文。不要在第一版尝试复刻 Bloomberg 或 Wind。

## 可能的数据源

| 数据源类型 | 例子 | 说明 |
| --- | --- | --- |
| 公开公告 | 巨潮、交易所；后续 SEC EDGAR | M1-2 已接入巨潮沪深年报查找下载，其他来源待扩展 |
| 上传文件 | 财报 PDF、研报、个人笔记 | 补充来源，不作为系统自动寻找公开年报的前提 |
| 免费行情 API | yfinance、Alpha Vantage、Finnhub | 适合学习和原型验证，需要注意额度和条款 |
| 中文市场工具 | AkShare、Tushare | 适合 A 股数据，稳定性和权限需要评估 |
| 付费 API | 金融数据供应商 | 等 MVP 证明有用后再考虑 |

## 工具结果的数据约定

后续资料、行情和计算工具分别返回可核对的结构，不把所有内容都转成一段模型摘要：

- 文档：文件标识、标题、披露日期、来源地址、页码与原文片段。
- 公开网页：地址、标题、获取时间、可确认的发布日期与正文；时间未知时明确标记。
- 行情：证券标识、所属市场、日期/时区、币种、价格口径、字段单位和数据源。
- 表格与计算：行列或时间序列、单位、公式和输入来源；缺失值明确保留。

研究截止日期与数据可用日期要对应；不能把后来披露的数据悄悄当作当时已知。图表、数据表和正文共享同一批结构化数据与来源引用。

工具目录与阶段见 `research-runtime-plan.md`；M1-2 的来源端点、缓存、限制与实际验收见 `m1-2-tools.md`。巨潮公开网站适配不等于拥有稳定商业 API；当前尚未实现多来源自动兜底。

## 架构原则

所有数据源都应该通过 Data Provider 封装。这样以后更换数据源时，不需要重写深研室、追猎者、锐眼这些工作流。

第一版中，Data Provider 优先放在 Python Agent 服务里，因为 Python 更适合处理行情库、文档解析、RAG 和数据清洗。Java 主后端只关心“我要什么数据/研究结果”，不直接绑定具体数据源。
