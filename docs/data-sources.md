# 数据来源

## MVP 策略

第一版由系统自动发现并获取公开原始资料，上传文件作为补充。M1-2/M1-3 已完成巨潮公开年报、半年报、季报及沪深股票日线；其他公告、研报和网页正文按后续任务接入。选定研究资料默认通读可提取文字并记录模型处理覆盖；搜索摘要与关键词不代替原文。不要在第一版尝试复刻 Bloomberg 或 Wind。

## 工具结果的数据约定

后续资料、行情和计算工具分别返回可核对的结构，不把所有内容都转成一段模型摘要：

- 文档：文件标识、标题、披露日期、来源地址、页码与原文片段。
- 公开网页：地址、标题、获取时间、可确认的发布日期与正文；时间未知时明确标记。
- 行情：证券标识、所属市场、日期/时区、币种、价格口径、字段单位和数据源。
- 表格与计算：行列或时间序列、单位、公式和输入来源；缺失值明确保留。

研究截止日期与数据可用日期要对应；不能把后来披露的数据悄悄当作当时已知。图表、数据表和正文共享同一批结构化数据与来源引用。

工具目录与阶段见 `research-runtime-plan.md`；报告来源/缓存见 `m1-2-tools.md`，动态阅读与行情见 `m1-3-agent.md`。巨潮适配没有多来源兜底；行情已有东方财富→腾讯备用。公开网站适配不等于拥有稳定商业 API 或转售授权。

## 已实现的行情口径（2026-10-24）

`apps/agent/app/tools/market.py` 的 `MarketProvider` 负责固定 HTTPS 端点、范围/证券/有限数值/OHLC 校验、交易日对齐和来源地址。东方财富 `push2his.eastmoney.com/api/qt/stock/kline/get` 取 `fqt=0/2`；失败后腾讯 `web.ifzq.gtimg.cn/appstock/app/fqkline/get` 取 `day/hfqday`。每组不复权/后复权都从同一 Provider 取得。

实际价格用不复权；收益变化、收盘回撤、波动及均线用后复权。网页默认将后复权收盘归一到起点 100，也可切实际人民币价格。字段单位、计算公式、请求/实际区间、获取时间和供应商均随数据返回；腾讯缺少的成交额不补造。

当前限制最多约三年日线，不提供实时、指数基准、估值、公司行动明细或严格时点复权快照。研究截止日限制报告披露和价格日期，但当前证券目录与本次复权因子不等同于全量历史时点数据库。中际旭创实际验收使用腾讯 486 个交易日；数据和原报告只保存在忽略目录。

## 架构原则

2026-10-24 补充：当前已在下载/哈希校验后的原 PDF 上，用 Poppler 渲染指定页并发送图片到 DeepSeek；仅声明实际视觉检查过的页。财务数字再与同页文本和单位匹配，形成同比/图表底稿，失败金额不进入图表。扫描页可以尝试描述，但没有文本对照的金额尚不能进入当前自动核对图表。图片渲染与模型处理/数值核对分别记录，见 `financial-research-skill.md`。来源范围仍是巨潮定期报告和现有行情，公开网页/其他报告来源没有因引入Skill自动接通。

所有数据源都应该通过 Data Provider 封装。这样以后更换数据源时，不需要重写深研室、追猎者、锐眼这些工作流。

第一版中，Data Provider 优先放在 Python Agent 服务里，因为 Python 更适合处理行情库、文档解析、RAG 和数据清洗。Java 主后端只关心“我要什么数据/研究结果”，不直接绑定具体数据源。
