## 本轮改动

- `RunLimits` 默认总模型调用上限由 72 调整为 144；分节写作接入后最后24次留给大纲、逐节正文、摘要、数据表、复核及局部重试，累计 token 预算200万中预留20万。小预算测试缩小预留，不绕过硬上限。提高容量之外，关键修复是取证与写作不再争用最后一次调用。
- 本地回查、命中缓存不新增模型调用，不应因为模型调用上限而禁止执行。取消、时间与实际模型调用的硬预算仍有效。
- 取证预算接近上限且基本证据齐备时，使用预留预算收尾；资料尚未通读或必要行情缺失时，如实保留未完成进展并允许接续，不虚构证据齐全。
- 每批成功阅读、已核对取数、工具完成、正文通过校验以及任务结束时写原子执行检查点。文件在 `storage/documents/run-checkpoints/{taskId}.json`，不入 Git、不含密钥；Java JSONL 仍负责业务会话记录。
- 新接续运行关联原任务，保留旧结果和旧费用。新尝试单独计量调用、token 与时间；旧用量通过 `continuation` 条目和 `run_resumed` 事件保留，不清除旧账。
- 新任务优先从执行检查点恢复。此次旧任务没有检查点，按 JSONL 当前 `parentId` 分支重建上下文、应用 `context_edit`，恢复实际保存的笔记、来源、覆盖、财务与业务数据；缺关键记录则拒绝接续，不假装恢复成功。
- 工具调用组只执行缺少结果的部分，先配齐工具消息再调用模型。原始参数有误时照常返回工具参数错误，由模型修正。
- 同一原任务的重复接续请求在当前进程内返回同一个子任务，避免双击并发计费；不承诺跨进程请求严格只执行一次。
- 图表列可由唯一列名/数字字符串转换为序号；无法理解的画图设置取消画图、保住有效表格。行列映射不明仍未实现可展示异常表，F16 仍为部分完成。

旧会话只显示近三年原值时，最早一年的同比基数可能未显示。保留旧报告已计算的同比，不从同比反推原值；只有原值与证据不变才沿用。接续导入已核对：38 批笔记、686 页覆盖、财务与业务 datasets 与原报告一致，不需要模型调用。

## 参考依据与边界

参考 [Pi 会话格式](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/session-format.md) 的父链与当前分支，以及 [LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence) 的检查点与成功步骤保留思路。采用这些机制的项目适配，没有引入整个框架，也没有把派生缓存等同于会话记忆。

用户随后要求将恢复作为产品能力，继续实现了 F17：`runner_writing.py` 先生成大纲，每节单独生成、校验实际引用、保存后再写下一节；最后仅根据完整正文形成摘要和预兆自评。正文每节最多6000输出token，不让整篇正文受单次输出长度限制。摘要阶段不重复附带整段取证历史，避免长正文与取证历史叠加超限。

暂时故障、输出截断与格式/引用错误只重试当前写作单元一次；仍失败则保留成功章节，并提供手动继续入口。章节快照同时进入原子检查点和 Java JSONL `report_draft` 条目，未完成报告也展示已保存正文。每次恢复从第一个未完成章节继续；如果只是摘要没完成，就只补摘要。已完成数据表阶段也有标记，不因复核失败而重生成数据表。半截无效章节不会算作已写完；取消和硬预算仍有效，不做无限自动重试。上下文摘要压缩、跨进程严格去重、Word/PDF 导出仍未完成。

隔离验证包括：第二节持续超时后重启恢复，只写第二节；两节写完在摘要前耗尽预算后恢复，只写摘要；无效引用章节不计成功；计划形成前账户故障恢复后补做未完成计划。失败原因带入下一次尝试，帮助修正当前单元。分节机制已通过离线检查，未额外收费重生成这份已经成功的天齐报告。
