# 公开补查必须实际取证，聊天空间还给正文

2026-10-25 开始，2026-10-26 收尾（Australia/Sydney）。仅修复当前搜索阻塞与工作台栏头，没有重新生成完整报告，没有提高总预算或更换模型。

## 原因与证据

失败追问 `7c2bc0d2` 的 JSONL 只有三次模型调用，没有一次搜索或网页阅读。每次旧上下文接近七万 token；模型直接用旧资料写答案，程序因缺本轮新证据要求修正两次，再强制收尾。把缺证据混成“修正格式或引用”的提示也不准确。因此这次是调度缺陷，不能归因成全网查不到。

直接测试现有 Exa MCP：行业关键词与大盘收盘关键词各得到五条候选网页（各排除一条不合条件的结果）。搜索服务确实可用，未接入新的付费服务。

## 核心改动与学习入口

1. `apps/agent/app/services/report_discussion.py` 的 `supplement_tool_choice`：明确要求补查且本轮无有效新证据时，用原生 named `tool_choice` 先要求 `search_public_information`；已有可读候选则要求 `read_web_document`。检索词和选读对象仍由模型决定，可拆多个主题；读站点失败两次后换候选/改词再搜。没有工具调用时不能把文字解释冒充搜索成功。
2. 同文件 `supplement_context`：只给报告提要、章节目录、近期用户问题、保存笔记与本轮工具结果。无需每轮重放旧长答案及研究流水。发现目录保留标题、网址、日期，未读摘要数字不进入答案上下文；已读笔记与准确引用保留。新增事实仍检查“本轮新增、读完、日期和引用合格”。
3. `agent_runner.py` 的 `model` 透传可选 `tool_choice`，`model_client.py` 沿用现有标准 assistant/tool 协议。工具执行、实际用量、逐条 JSONL、分支、检查点仍走原入口，没有旁路虚构工具结果。
4. `ReportWorkbench.tsx` / `ResearchPreview.tsx`：过程记录、版本、字号、分支改为工具条入口，详情在 `WorkbenchDialog.tsx` 原生 dialog 弹层中，不再占聊天竖向空间。Esc/关闭后恢复入口焦点。报告/聊天开合、拖宽、字号、全部过程与旧分支仍可用。

本次**没有新增逻辑工具**。实际使用的是已有两个：`search_public_information`（按关键词发现网页）和 `read_web_document`（抓取选中正文、分批完整阅读并保存证据）。底层在 `tools/public_web.py`（Exa MCP/官方 Fetch MCP）和 `services/runner_web.py`（发现、快照、阅读覆盖与笔记）。

调用链：用户再查 → 小上下文选检索词 → 原生工具调用 → Exa 返回目录 → 模型选读 → Fetch 完整正文/阅读笔记 → 基于本轮已读证据回答 → 引用校验 → JSONL 保存 → 聊天框。

## 官方参考与实现选择

- [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) 区分 auto、required 与指定函数；auto 允许直接回答。指定函数要求关闭 thinking，本项目原客户端已经关闭。本轮采用标准指定函数机制，把“明确补查先检索”的业务要求接上。
- [DeepSeek Search / Fetch](https://api-docs.deepseek.com/guides/search/) 是独立联网 API。DeepSeek 确实提供搜索，但普通 chat 请求不会因为换了模型名称自动连上搜索。本项目本轮仍使用已有 Exa/Fetch MCP；没有声称已接入 DeepSeek 原生搜索。
- 保留已有 Pi 式消息/工具循环与追加会话，参考见 `agent-design-decisions.md`，没有放宽来源真实性条件来换取表面成功。
