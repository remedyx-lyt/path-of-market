# M2-2：单用户研究记忆与偏好

2026-10-25（Australia/Sydney）。按用户要求先完成记忆，再接MCP，随后准备GitHub展示。本轮已接入程序与网页，使用隔离模型/资料验证，没有调用真实模型账户或重生成报告。

## 产品中怎么用

研究输入区下面新增“研究记忆与偏好”。展开可查看研究对象、提问主题、原问题与来源链接；添加/修改/移除长期偏好，确认或忽略模型建议，排除某个对象的历史经历，或关闭记忆。查看、刷新和手动编辑均不调用模型。

例如过去分别研究过中际旭创、天齐锂业，系统会记下实际研究经历；若用户多次提出现金流/应收问题，会显示带原提问依据的主题观察。用户确认“先解释现金流，再给反方证据”后，新研究的方法计划、研究循环、报告写作及报告旁追问都能参考它。本次问题/风格/日期始终优先。

## 三类内容分清

| 内容 | 来源及更新 | 如何使用 |
| --- | --- | --- |
| 研究经历 | 已落盘且成功完成的研究请求/追问，自动聚合；失败任务不算完成，刷新和重复查看不增加次数，修订版不额外算一次研究 | 跨会话知道研究过谁、问过什么，附原任务/节点/日期；不把旧报告的金融结论当当前事实 |
| 主题观察 | 最近30次成功任务/追问，按明确关键词归类现金流、资产负债、业务竞争、成长研发、风险、股价估值，并附最多3条问题依据 | 属于近期研究兴趣线索；**含程序默认问题，因此不能等同于用户亲自表达的长期偏好**，也不推断持仓或风险承受力 |
| 确认偏好/候选建议 | 用户直接编辑为确认；模型调用工具提出带当前用户原话的候选，用户可修改、确认、忽略 | 仅确认项进入长期偏好上下文；候选不自动覆盖或混入确认项，不后台独立发收费的画像摘要请求 |

偏好类型是研究偏好、风险关注点、观察对象。它们是本机唯一用户的资料，不是多账户推荐系统。候选可以由模型在正常研究/追问中提出，不保证每轮都产生。查看某家公司不意味着看多它；历史问题也不属于已经核验的财务数据。

## 参考依据及实际适配

- [Claude Code memory官方说明](https://code.claude.com/docs/en/memory)：持久指导与自动学习笔记跨会话加载，内容可检查/编辑，短索引与详细记忆分开。本项目按单用户研究业务保存结构化笔记、开关与原话来源，没有复制其文件格式或声称接入Claude的内置记忆。
- [OpenAI官方个性化记忆示例](https://developers.openai.com/cookbook/examples/agents_sdk/context_personalization#techniques-covered)：状态保存、相关上下文注入、工具记笔记、合并/去重及移除过时内容。本项目采用候选→用户确认的整理过程、按需回查与去重；仍调用DeepSeek，不引入OpenAI SDK/额外密钥，没有训练模型。
- [LangChain记忆概念文档](https://docs.langchain.com/oss/python/concepts/memory)：同一对话的短期状态与跨会话长期记忆分开，画像/条目集合各有取舍。本项目采用小型结构化笔记集合与历史经历索引，没有为单用户先引入向量数据库。
- 既有Pi式JSONL负责原会话/父链；长期偏好独立保存。M2-5摘要整理本次历史；M2-2跨研究带入用户偏好，两者并行，不能把摘要或PDF缓存冒充长期画像。

## 代码与调用关系

React `UserMemoryPanel` → Java `ResearchMemoryController`/`ResearchMemoryStore` → 本地记忆文件及会话中的用户输入索引。

开始研究/追问 → Python `load_user_memory()`（只读一次本轮快照）→ `memory_preferences()`参与`method_task()`及计划缓存键 → `memory_context()`放在每次请求的当前尾部 → 正常模型/工具循环。压缩较早历史不会删掉这个独立记忆快照。UI修改在下一次研究或追问生效。

## 新增两个逻辑工具

1. **`recall_user_memory(query, limit)`**：按公司名/问题关键词读取跨研究经历与确认偏好。每次最多10条经历，不发模型请求，也不重新读PDF。它不是向量语义搜索；原始财务笔记继续用M2-5的`recall_research_context`。
2. **`remember_user_memory(text, category, quote)`**：保存待确认研究偏好。Python先核对quote逐字来自本次用户输入，先将用户请求落盘；Java再核对当前runId的原话。不能引用年报、模型回复或另一运行的用户原话。不覆盖确认项；格式/来源/服务不对时返回工具错误。

模型决定调用工具及随后答复仍属于正常模型调用；工具中的Java读写本身不调用模型。本轮逻辑工具从7个增至9个，底层公开资料/行情工具仍8个。

## 保存、恢复及控制

- 偏好/候选/开关/忽略对象保存在默认`storage/sessions/memory/user.json`，在已有`storage/sessions/`忽略规则内，不进Git。研究经历来源仍是原始会话JSONL，GET只做投影，不悄悄创建偏好文件。
- 同目录临时文件→刷盘→原子替换（平台不支持时退回替换），失败保留原文件；编辑带revision，旧页面提交返回409，避免静默覆盖另一处修改。
- 同文候选去重；移除偏好或忽略候选会删掉记忆文件中的正文/原话，仅保留指纹防重复（最多最近256个）；原研究会话独立保留，不把移除画像说成删除原聊天。
- 最多48条有效偏好/候选，每条500字符。上下文使用已确认项、最近5个对象、最多3条相关问题和主题名称/计数；更多历史用工具按关键词回查。未实现Embedding召回、自动实体别名合并、批量模型画像总结或时间衰减评分。
- 关闭开关后，新任务不注入偏好/经历，也不新增候选；保留原记录供查看。忽略某公司只排除其研究经历/主题统计，独立确认的观察池偏好可另行移除。可恢复忽略对象。
- 记忆读写错误、损坏或服务不可用不清空旧文件，也不让成功研究变失败。研究按本次输入继续，活动记录明确标记未使用记忆；不能声称写入成功。
- Agent读取记忆时排除当前报告rootTaskId的所有经历，当前报告的问答只沿所选父链进入上下文，避免长期记忆旁路带入另一分支。网页总览仍展示全局经历；其他独立研究可跨会话回查。用户明确确认的全局偏好可跨分支参考。
- 个性化记忆会随正常研究请求发送给所配置的模型服务；本地保存与不提交Git不等于模型请求完全离线。
