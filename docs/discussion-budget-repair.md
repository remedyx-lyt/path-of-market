# 报告追问的预算与上下文修复

2026-10-25。用户追问“补充官网以外的公开资料，直接文字给我”失败于`token_budget`，本项优先修复。财务来源冲突自动择源是另一项待处理问题，本轮没有改动其规则或原报告。

## 实际原因

失败任务`7b547bbf`保存了5份新增网页的全文阅读记录，累计19次模型调用、1,022,664 tokens。不是没有找到资料，也不是1800的单次输出设置导致。

1. 聊天重放完整研究历史，包括旧草稿/方法/取数过程。每轮额外注入整份报告，还包含已存在于独立底稿的表图与日线序列；这部分在历史压缩边界外，摘要不能缩小它。决策输入约12万至14万tokens。
2. 用户说“直接文字给我”，模型返回裸Markdown，程序要求`FollowupAnswer` JSON；修正后又引用未读网页/未知日期网页。旧校验只说“引用不合格”，没告诉模型具体哪条。
3. 预算只看上一调用累计用量，单次大输入会跨过预留线；聊天没有像主报告一样转入收尾回答，于是已有新资料也只留下失败提示。

## 改了什么

- `discussion_context.select_history`：第一次聊天从研究流水切换为当前报告+聊天父链；旧失败聊天通过保存的消息ID定位边界，保留该分支问答与完整工具组。检查点保存`discussion_context_version`。原JSONL、阅读记录、来源与精确底稿不删除；已迁移聊天摘要边界继续复用，无可靠边界时不猜测删历史。
- `report_view`：每轮带正式摘要/章节/引用与序号，不反复带整份日线、表图和重复底稿。原笔记按来源/批次回查；`recall_research_context(kind=report_section)`现在也可取该章原表格，避免压缩输入后失去表格细节。
- `saved_supplement`：单独注入报告后新读资料的笔记、日期与来源。补查已有有效新增资料却只引用原报告时拒收；没有新增可引用资料则明确标注补查未完成。校验能确认引用指向实际阅读，不能自动证明每个论断与原文语义完全一致。
- 收尾只保留搜索发现目录，不把未读摘要数字反复传给模型；日期/阅读条件不合格网页不传正文事实。提示明确要求未通读资料只列标题与待核问题，不将其数字写入补查结论。
- 对话仍为原来的**100万token、72次调用、900秒**，没有调高总预算。增加下一调用的保守字符估算与收尾预留；接近取证token/调用/时间/上下文边界，补齐未执行工具的延期结果，用已读证据回答，列明缺口。字符估算不是精确tokenizer，仍按供应商实际用量记账；硬性账户/网络/格式失败仍保留恢复入口，不能承诺永不失败。
- 开始回答后只修回复，不重开搜索；最多两次格式/引用修正。诊断记录具体无效sourceId/page，未知日期仍不能冒充截止日证据。同一预算失败问题已经补查全文时直接利用保存笔记回答。

没有增加模型工具。沿用现有11个逻辑工具，新增的是上下文选择、补查引用要求和预算收尾。
