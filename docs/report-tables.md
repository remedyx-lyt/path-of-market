# 报告数据表、必做图表与负债口径（2026-10-24）

M1-4 真实验收后，用户反馈：报告与图表偏少；产能、产量、销量这类经营数据只在正文里、没有表和图；资产负债表缺负债。用户要求：已有图表全部保留，让模型根据读到的内容**额外**做表做图；用户点名的几类是必做项。对应任务板“用户优先补充（三）”的 F3、F5、F6、F7。

## 一、改了什么、为什么

| 问题 | 根因 | 处理 |
| --- | --- | --- |
| 负债缺失（F3） | 母公司资产负债表常跨页。原规则只截掉同一页“2、母公司资产负债表”标题之后的文字，第 93–94 页上半部分的母公司“负债合计”（38.29 亿）被当成合并总负债（136.68 亿），两数相撞判为冲突，都不用 | `consolidated_text()`：每页开头沿用前面最近一个报表标题的口径，页内遇到新标题再切换；“三、公司基本情况”起回到默认口径。只把合并口径文字交给取数 |
| 经营数量数据没有表（F5） | 取数工具只认金额与 13 项财务指标，不认“万只、吨、台” | 程序定位产能/产销量表所在页（`locate_operating_pages()`），研究中提示模型回查；写作第二步必须给出这张表 |
| 只有程序预定义指标能画图（F6） | 设计上只画程序核对过的固定指标 | 模型根据已读原文自行决定要做哪些表，可选画柱状图或折线图；程序逐格核对数字是否出现在所引原页 |
| 收入结构、资产负债图有时没放（F7） | 由模型选图，可能漏掉 | 程序兜底：多板块收入结构图、含负债的资产负债图，漏放时补到对应主题章节（单一业务占九成以上不强制） |

## 二、数据表怎么生成：正文与数据表分两步写

带表格的整篇报告一次输出 3–5 万字符的 JSON，真实运行中多次写坏（漏 `"cells":[`、括号错位、正文英文引号未转义），每次都要整篇重写。改为：

1. **正文**（`compose()`）：章节、文字、图表 ID、定性图，不含表格。规则 `REPORT_RULES`。
2. **数据表**（`add_tables()`）：与研究阶段共用上下文前缀（缓存可命中），输入章节列表，只输出 `{"tables":[{"section":序号,...}]}`。规则 `TABLE_RULES`。每张表单独整理与校验，不合格的去掉并记下原因（`tables_dropped` 事件），不影响正文和其他表。必做的产能/产销表缺失时补要一次，仍缺则写入报告局限。
3. **复核**（`review()`）：不带表格（表格已由程序核对），复核后按章节原样挂回；复核调用出错或复核稿不合格时，保留复核前已通过核查的报告。

表格格式（`SectionTable`）：`title`、`unit`、`labelHeader`（行名列表头）、`columns`、`rows[{label, cells, sourceId, page, alsoFrom, note}]`、`chart`（none/bar/line）、`chartColumns`、`note`。一行跨多期、数字来自不同报告时用 `alsoFrom` 补充来源页。

**逐格核对**（`check_table()`）：含数字的格子，其中每个数字须出现在本行所引原页；允许“元→万元/亿元”换算（按表中小数位四舍五入）。核对不上的格子在网页上标 `*`、颜色变浅，说明“未在所引原页找到，多为计算值”。核对结果随报告返回（`verification`）。

**程序能确定意图的机械问题直接整理**（`normalize_table()`，均记录事件）：把行名表头写进 `columns`、格子写成数值、页码写成文字、画图设置写进行里、画图列超过 4 列；整理后行列仍对不上的表去掉。

## 六、真实运行

同一任务（中际旭创，截止 2026-10-23）共跑了 8 轮 A、B，每轮暴露一种模型写法问题，逐个改为程序整理后再跑。按出现顺序：

| 轮次 | 暴露的问题 | 处理 |
| --- | --- | --- |
| 1 | 表格行名表头写进 columns、文字格子超 40 字、行情行无页码、“可以写了”的非标准写法 | `normalize_table()` 移出表头；格子上限 120 字；行情行页码可空；`wants_to_write()` |
| 2 | 复核时报告被包进 `candidate`、写到 14 节、表格数字因元→亿元换算对不上 | 拆外层；超出章节合并；`found_on_page()` 允许单位换算；行可加 `alsoFrom` |
| 3 | 带表格的整篇 JSON 写坏（正文英文引号、漏键、括号错位） | 正文与数据表分两步写；`escape_inner_quotes()` |
| 4 | 复核要重写整篇（含十几张表）超出输出、复核出错导致整个任务失败 | 复核不带表、完成后挂回；复核出错保留原报告 |
| 5–6 | 表格被整批丢弃 | 记录每张表被丢的原因、存档原始回复；查明是格子写成数值、行内多了 `note`；转文字、允许行 `note` |
| 7 | 自拟图表 ID、定性图节点无来源 | 不存在的 ID 去掉；无来源节点去掉，不足 2 个则不放 |
| 8（最终） | 行内写 `pages` 列表导致产能表被丢；另一张表引用同一页被误当成已有产能表；行情行填了页码 1，前端校验拒收 | `pages` 拆为 `page` + `alsoFrom`（存档回复重放后产能表合格）；产能表须标题/列名含产能/产量/销量/库存；行情行页码清空，前端与后端一致 |

## 七、边界

- 表格是模型根据原文整理的；程序只核对数字是否出现在所引原页，不核对口径是否恰当。计算值（利用率、占比、同比）标为“未在原页找到”，是提示而不是错误。
- 分工厂/基地产能只有年报披露时才会出现。
- 2026-10-24 审查订正：此前是服务进程找不到 Poppler，检查终端可以找到，并非历史上从未成功。F18 已改用项目内 pypdfium2/Pillow 子进程，重启后实际工具渲染通过；本轮没有额外调用视觉模型。见稳定性审查。
